# 可配置快照任务与 100,000 候选

本设计将“目标、时长、来源范围、来源最低量、请求预算”分开配置。
10k/20k/50k/100k 是方便选用的模板，不是采集器固定容量。
本版可生成目标 1—100,000、时长 2—168 小时的新任务；这是新配置的有限安全范围，
不是 Amazon 的来源容量结论。更高数量以后必须按新契约单独扩展。

## 新任务配置

`CURRENT_PAGE_TASK_CONFIG_V2` 支持以下独立参数：

- 目标：当次全局去重合格候选组，仍不等于已确认可售 ASIN。
- 时长：包含采集、冷却、中断和最终审查；达到时限即停止，不保证达到数量。
  暂停和恢复都不重置时钟。保留至少一小时 QA 预留及既有实测耗时公式，
  所以当前不提供少于两小时的 LIVE 任务配置。
- 三榜最低量：逐榜检查，同时还要满足全局独立去重目标。三榜存在重叠，不能相加当独立 SKU。
- 来源范围：可提供已审 root source_id 的子集，不能凭配置增加未经审查的来源；
  选出的范围仍必须包含三个规定来源族。
- 每榜 PAGE 预算：请求数与 PAGE 数相同、native 为零。每榜及总量最多 60,000，
  仍保留三秒共享请求间隔和至少 1,800 秒类目冷却，不因数量增大提高访问频率。
- 原始观察与历史存储上限：均有限，V2 最多 2,000,000 条。原始观察不是去重候选。

模板中的时长和预算都只是默认值。100k 模板默认 72 小时、10,000 PAGE 请求：
畅销榜4,400、新品榜4,400、喜爱榜1,200；最低量30,000/30,000/3,000。
这不证明能抓到十万，也不证明有限时间能耗尽全部预算。来源不足、预算耗尽、
QA预留到达或访问受限时应保存未完成结果及缺口，不能补重复条目、改目标或自动延时。

```powershell
# 短任务：目标 1,000，包含审查的总时限 2 小时
amazon-es --offline snapshot profile --target-count 1000 --duration-hours 2 --out short.pending.json

# 自定义数量和时长
amazon-es --offline snapshot profile --target-count 23750 --duration-hours 6 --out custom.pending.json

# 100k 模板；也可用 --target-count 100000 --duration-hours 48 覆盖默认时长
amazon-es --offline snapshot profile --target-profile main-priority-100000 --out 100k.pending.json
```

`--source-minima` 和 `--page-budgets` 接受三来源 JSON 映射，
`--source-ids` 接受已审来源 ID 列表。参数仅生成 pending 配置。
`prepare-page` 从原计划的已审根来源生成全新 run_id、计划、待审批记录和独立时钟路径；
不创建时钟、不打开浏览器、不继承旧任务的预算/时间扩展批准。

## 与正在运行任务的隔离

旧 10k/20k/30k/50k 策略仍做精确值校验，不能改旧 profile 的 target 来变成100k。
配置的目标、总时长、来源最低量均进入计划哈希；新策略的时长必须与计划一致。
已有时钟绑定 run_id 和计划哈希，更改目标或时长后重用原时钟会被拒绝。
当前5万任务的计划、三窗口修订、预算、截止时间和断点一律不修改。

三窗口是独立的执行修订，不是数量模板隐式授权。100k 或自定义任务要运行三窗口，
仍需绑定该新计划、来源审查、代码验收、原配置、门禁和Spain UI证据。
旧三窗口批准不自动授权新100k任务，也不能换配置/账户规避访问停止。

## 验收范围

离线覆盖自定义配置、旧策略不变、时长/目标篡改、时钟重启不延长、
99,999→100,000增量计数边界与跨榜重复不增量。100k合成记录仅验证统计规模，
不构成来源供应、网络吞吐、全DOM审查时长或生产十万采集完成的证据。
最终仍需实际原始证据、请求凭据、全量统计、DOM审计和交付回读。
