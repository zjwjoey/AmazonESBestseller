# 新快照：20,000 候选，喜爱榜最低 3,000

2026-10-21 最新任务口径。旧的 30,000 / 每来源 5,001 计划和历史证据保持原义。

## 数量和身份

- 新配置 `MAIN_PRIORITY_20000_FAVORITES_3000_V1`：全局至少 20,000 个去重保守候选组。
- 畅销榜、新品榜为主，沿用两个主力来源各至少 5,000 的基线；不强制等额分配剩余数量。
- 顾客喜爱榜至少 3,000，达到最低量后优先继续两个主力来源。页边界可能略超目标。
- 商品 URL 和观察记录是快照依据；ASIN 提示可缺失，不能把候选数量宣称为已核验可售 SKU 数量。
- 卡片 ASIN 与链接提示冲突时保留原值、标记 `CONFLICT`，排除该记录的合格计数，继续其他卡片和来源。
- 不绕过正式详情身份门禁。证据损坏、请求不在审核范围、访问受限不属于可忽略的单商品冲突。

## 一级类目

新配置绑定 `SOURCE_CATEGORY_IDENTITY_V1` 元数据版本，旧快照回放不被静默改写。

- `amazon_category_l1` / `amazon_category_path`：只从实际 Amazon 导航链，或首页同一商品轮播对应的栏目链接与根类目导航匹配取得。
- `source_category_l1_raw` / `source_category_status` / `category_evidence`：保留来源一级上下文和证据。
- 喜爱榜主题标签可保存为来源上下文；未证明为正式 Amazon 一级类目时，不把主题名强填入 `amazon_category_l1`。
- 混合首页逐卡片绑定栏目，不能把页面第一个类目赋给全部商品。
- 类目证据缺失的原始观察保留，标记 `CATEGORY_EVIDENCE_MISSING`，不计入新任务合格目标；不会因此退出整批采集。
- `snapshot_eligible` 与存储层去重索引的 `target_eligible` 分开，避免索引覆盖质量隔离结果。

## 运行入口和配送

使用本工作树的 `scripts/snapshot-v4.ps1`。脚本显式设置本仓库 `src` 为导入路径，避免系统 editable 安装指向其他旧 checkout。

离线查看命令：

```powershell
./scripts/snapshot-v4.ps1 prepare-snapshot --help
./scripts/snapshot-v4.ps1 configure-delivery --help
```

`prepare-snapshot` 默认新配置。输入必须为当前审核的 `V4_MAIN_PRIORITY_SNAPSHOT_SCOPE_PROPOSAL`，包含真实来源、精确页面 URL、有限来源预算和当前任务目标。新配置不再要求旧任务固定的 897 个来源 / 1,102 个 URL，但仍逐项校验导航、证据哈希、来源范围与前置验收。只生成待审计划，不自动启动或授予执行权限。

`configure-delivery` 必须显式 `--live`，只通过现有程序设置/核对西班牙邮编。使用固定 `--profile-dir`，每次证据目录必须是新目录；设置失败时保存当前 HTML、真实可获得的 HTTP 状态与错误，不自动重试，不伪造请求收据或更新共享 Access Gate。

新配置实际采集必须复用同一个浏览器配置目录。每个已请求来源页在解析前检查该页配送头部；不是西班牙或无法确认则保存已取得的收据并暂停。不会用页脚“España”替代配送目的地证据。

## 当前 PAGE 模式

`CURRENT_THREE_SOURCE_PAGE_SNAPSHOT_V1` 复用 V4 串行请求、存储、回放和访问门禁。它只执行普通来源页面请求，禁止 native ACP / dynamic 请求；不宣称旧的八来源 T1/T2 容量与加载验收通过。

- 前置证明 `CURRENT_THREE_SOURCE_PAGE_PROTOCOL_V1` 必须从本次三个入口的实际请求预留、200/NORMAL 收据、原始 HTML、配送头部与完整 DOM 回放重新验证，不能用报告里的 PASS 字段替代。
- 正式来源按审核的实体一级部门分组。根部门来自已保存的导航锚点；喜爱榜保留可核验的来源上下文，缺少当页正式类目证据时不虚构 canonical 层级。
- 同部门内按广度优先访问已批准入口和导航。只有已提交的本轮正常页面里实际出现的 owned 子类目与连续 Next 才可入队；每项绑定同批父收据、原始锚点、计划哈希和批准根部门。
- 深度最多 6，每个根部门最多 120 个来源，每来源最多 160 页，并受全局和分来源预算限制。未知 URL、搜索 facet、跨部门链接和猜测页码不能入队。
- PAGE 快照在一级部门之间直接接续，不再冷却。每次发送仍检查共享限速、门禁和预算；原密封计划、时钟及历史冷却字段保留为证据。
- 新任务最多 24 小时，预留至少一小时离线 QA 时间；旧 30,000 专项的十小时契约不变。预算耗尽或来源范围用完且不足目标时不能宣布数量验收成功。
- `snapshot_progress.json` 区分全局合格去重组与原始观察，喜爱榜不足 3,000 时全局 20,000 也不能验收。离线 fake 传输器测试不得计入本轮实采数量。

2026-10-21 程序已实测配送为 Madrid 28001，三个根入口均实际返回 200/NORMAL：217 条原始观察、215 个 URL、71 个带合格类目证据的候选组。这只是当前入口验证，不是新正式任务的数据种子，也不证明喜爱榜具备 3,000 容量。实采的持续进度和停止原因以独立运行目录为准。
