# Three-window PAGE snapshot execution

The parallel entry is `python -m amazon_es_bestseller.highspeed.parallel_cli`.
Use `check` with the original plan, authorization, an independently bound parallel
amendment, tested source manifest, store root and code root. Checking reads an
isolated database/WAL copy and never launches a browser.

An explicit `resume --live --release-pause --profile-dir ...` additionally requires
the passing isolated acceptance report and current normal-UI Spain delivery.
The original sealed plan, task clock and source budgets remain unchanged. PAGE
snapshots no longer wait between categories. Legacy cooldown values remain as
historical evidence and do not gate scheduling; unsettled claims still prevent
cross-category work. Three fixed windows share one persistent context and a global dispatch
gate; requests remain bound to durable reservations and per-window source scope.
Any observed access restriction closes all new dispatch and persists the access
stop even if response-body capture fails. Uncertain claims remain held for review.

The same run resumes from saved page evidence. Tracking-link aliases require
separate exact-path and sealed-navigation proofs; they are never fuzzy matches.
Captured documents, rendered evidence and original PAGE parsing/audit are retained.
Snapshot candidates remain unverified product identities until the existing
identity authority confirms their ASINs. Reaching a quantity is not final acceptance.

Run portable regressions with `pytest tests/parallel`. Browser integration uses
installed Chromium and local intercepted fixtures, with no browser downloads or
Amazon requests. Frozen machine-specific checkpoint tests are disabled by default;
set `SNAPSHOT_LOCAL_CHECKPOINT_TESTS=1` only against the explicitly frozen local
evidence they reference. Production data, browser profiles, authorization records,
logs and execution receipts must remain outside Git.
