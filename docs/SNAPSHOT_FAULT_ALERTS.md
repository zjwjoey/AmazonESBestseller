# PAGE 快照异常处理与桌面提醒

当前入口：`python scripts/amazon_es.py snapshot parallel-check ...` / `snapshot parallel-resume ...`。
规划、检查和帮助均不启动采集；恢复仍需原计划、原时钟、当前代码清单、新版隔离验收、原配置和西班牙配送预检。

## 旧程序清理

删除 `Invoke-HighSpeed.ps1`、`Invoke-Multisource.ps1`，删除旧 V2/V3 LIVE 浏览器执行体，停止生成 `Start-Reviewed-V3.ps1`。
保留历史离线回放、原始证据、查询、ASIN 身份及当前 PAGE 依赖的底层组件；正式 `detail-plan` / `detail-run` / `task-collect` 不属于退役范围。

## 异常分级

| 情况 | 请求处理 | 进程和提醒 |
| --- | --- | --- |
| 单窗口页面打开、响应体或 DOM 读取失败 | 持久停用该窗口，将未确认请求留置，其他正常窗口在原类目和预算内继续 | 保存异常堆栈并弹窗，不重试、替换或转移失败请求 |
| 403 / 429 / Challenge 等访问停止 | 按该任务明确批准的 `access_stop_scope`；`worker` 仅停该窗口，`all` 保留全停 | 原检测不变，保存访问证据和提醒；受限窗口不可自动恢复 |
| 响应日志、队列、身份绑定、页面提交或中央审查故障 | 全部停止派发，已发出的请求尽力保存，不宣称成功 | `PAUSED_ERROR` / `WAITING_FOR_OPERATOR`，保留进程和浏览器窗口 |
| 留置请求阻止跨类目或没有可用窗口 | 保留断点，不跨类目跳过、转移预算或重发 | 全部等待人工处理并提醒 |

旧封存修订中的 `access_stop_scope=all` 不会被软件偷偷改写。新 `worker` 修订必须同时批准 `fault_handling_contract=PAUSE_ALERT_V1` 并通过新版代码清单与隔离验收。
暂停包含在原总时长内；即使原时钟已到期，等待界面也不会自动申请新时钟或恢复网络。
参数错误和未获批准的启动在浏览器创建前拒绝；程序存活不代表采集仍在进行或任务已完成。

## 弹窗与操作

Windows 使用独立的无控制台提醒进程显示警告，避免弹窗阻塞证据写入。内容包含任务、窗口、范围、异常摘要和错误记录位置。
弹窗只有确认按钮；关闭或确认不会恢复采集。Linux/无桌面环境保留控制台提示和同一错误文件。
`store/alerts/*.json` 保留完整异常堆栈、阶段、请求 ID、URL、原计划哈希和时间；另存通知投递状态。
主存储无法写入时，错误记录尝试保存在 F 盘独立 fallback 目录；通知失败不会覆盖原始异常或放行请求。

查看当前等待记录：`store/alerts/waiting.json`。
只确认已读：`python scripts/amazon_es.py snapshot alerts --root STORE --run-id RUN_ID`。
结束等待并退出程序：加 `--exit-wait`；这个动作仅结束等待，随后收尾，不恢复采集。
也可 Ctrl+C 退出。控制文件绑定本次 wait ID，旧确认记录不能释放后续等待。
处理故障后的恢复仍须单独审查留置请求、门禁、证据和原时钟，不能通过点弹窗或删除停止记录恢复。

## 验证边界

离线回归覆盖：页面超时、403、共享写入异常、正常窗口继续、未确认请求留置、禁用窗口重开后仍禁用、进程和 context 保留、通知失败 fallback、确认不恢复、旧控制文件不生效。
本地浏览器集成全部拦截为已保存 fixture，不发送 Amazon 请求，不使用真实浏览器配置，不构成 LIVE 或十万真实采集验收。
