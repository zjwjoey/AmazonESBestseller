## 本轮确认的代码风险

### HIGH：结构化 checkpoint 只在整批完成后保存

`cli.py:170` 调用 `collect_details` 返回后才更新、保存 DetailState；`detail.py:763` 也只在完整循环结束后写 `details.json`。遇到 AccessStopError 或进程中断时，已下载 HTML 尚在，但新成功记录未形成及时 checkpoint。556 个 HTML 与 344 条状态的差异正说明了这层断开；不能因此说原始数据全部丢失。

`planning.py:85` 直接覆盖状态 JSON，尚无临时文件原子替换；读取失败时又退为空状态。扩大任务后应防止断电/中断导致状态损坏并退化为全量恢复。

### HIGH：隔离补丁误改原始榜单，且没有任务级失败记录

`cli.py:137–145` 只凭 quarantine 中 HTML 文件名过滤 `rankings`，发生在 `--rankings-only` 分支之前。这会因为某个 SKU 详情失败而删除原始榜单出现记录，违背“榜单记录和商品记录分开”的契约。隔离状态应影响详情执行计划，不应删除真实榜单证据。

文件名规则不区分挑战/普通无效/复核结论，也没有过期或显式恢复机制。`tests/test_cli_smoke.py:96` 的新测试只验证 rankings-only 被过滤，并未验证真实详情续跑到下一 SKU，反而固化了上述错误行为。

### HIGH：普通无效商品页仍会终止整批

`detail.py:720/751` 将 `INVALID_OR_EMPTY` 同样抛为 AccessStopError。隔离补丁只能处理已经在 quarantine 中的 ASIN；遇到下一个新无效页仍会停止。需要保留真正的 CAPTCHA/403/429 停止策略，同时对普通无效页面和身份冲突实行可追踪的隔离处理，不能直接把解析失败定性为 Amazon 源不存在。

### HIGH：刷新规划和执行不一致

`planning.py:179–190` 可以把缺字段或过期记录列为重采/刷新，但 CLI 传给采集器的只有 ASIN。`detail.py:692–729` 发现同名 HTML 就直接离线恢复，无条件跳过网络访问。因此计划标记“刷新”并不保证实际刷新。重解析记录又可能通过 `DetailState.update` 得到当前时间，掩盖原始证据年龄。

最新“只重解析旧 schema”的修改确实避免了无旧记录时全量预解析，但并没有修好上述刷新语义、HTML 与 state 的增量恢复、无进度和 checkpoint 问题。

### HIGH：任务清单可以静默少条

`cli.py:154` 只取 manifest 与 rankings 的交集，除非交集全空，否则不验证全部目标是否存在。`planning.py:159` 从 `pages_seen` 取 ASIN，缺少 ranking_source_url 的输入不会加入计划。

本次离线最小诊断：输入一个合法 ASIN、没有来源 URL，`build_plan` 返回 total_asins=0 / collect=0 / skip=0。对于要求真实来源的任务，应报告输入错误；不能悄悄忽略。导出也未接收任务 manifest 进行最终足额对账。

### HIGH：部分翻译可能永久停在 partial

`translation/ds.py:297–300` 对 source hash/schema 相同的 partial 缓存直接返回；普通重跑不会补齐缺失字段。本次离线诊断使用禁止联网的替身证实：partial 返回 partial，翻译调用次数为 0。缓存复用本身合理，但必须增加显式的部分翻译修复流程。

### MEDIUM：大批量字段审查一次加载全部 HTML

`qa/field_closure.py:223–235` 建立 ASIN→完整 HTML 字符串字典，`audit_field_closure` 一次加载后才逐商品审查。当前 556 页约 1.44 GiB；如果未来页面体积相近，5000 页原文件约 13 GiB，运行内存还可能更高。这是容量外推，不是本机 5000 页实测；需要流式/逐页审查和压力验证。

### MEDIUM：无完整运行状态/阶段进度

`run_manifest.py` 已有字段和读写函数，但生产采集主链未调用它们。成功页面没有逐页状态输出，失败原因只打印；批次末尾输出不能支撑长任务诊断。此前凭空白页面就推断配置锁、后台会话或网络故障没有充分依据；后续最小 Playwright 测试成功，已证明不能据此判定 Playwright 无法访问 Amazon。

### MEDIUM：源覆盖和工作表规格需要统一

当前候选集只有 2430 个唯一 ASIN，不能直接从它选出 4000–5000。跨组分类校验目前主要针对 car，其他组需要代表性验证。

代码和主 MD 为三表，历史用户需求曾指定正式交付两表；应把正式产品表和内部类目规划的用途统一写进契约，而不是本次审查直接改表。
