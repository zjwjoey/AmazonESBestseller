# Amazon.es 采集主链加固设计

日期：2026-08-26  
状态：已获用户批准，待用户审阅本设计后进入实施计划

## 1. 背景与目标

当前主仓库的离线回归测试可以通过，但审查发现若干会影响 SKU 身份、价格语义、断点恢复和导出可靠性的缺口。本次只做聚焦加固，保持现有 `collect → enrich → qa → export` 主链、低频串行访问策略和三表 Excel 契约不变。

目标是：

- 详情页内容必须与请求 ASIN 一致；重定向或未知页面不得写入正常商品记录。
- 原价、折扣率和月购买量遵循已有数据模型，不猜测缺失值。
- 断点恢复继续可用，但恢复文件也必须经过完整访问状态门禁。
- 人工备注按 ASIN 保留，自动重跑不能覆盖已有人工内容。
- CLI 可以明确接收图片缓存和类目规划，避免默认导出静默缺图/缺规划。
- 仓库可以在新 Python 环境中按声明的依赖安装，且保留离线测试入口。
- 用离线 fixtures 和回归测试锁定以上行为，避免依赖重复访问 Amazon。

非目标：代理池、并发采集、验证码/风控绕过、全站重采、已有历史 Excel 产物的批量改写。

## 2. 方案选择

### 方案 A（采用）：现有模块上的最小加固

在 `collection/detail.py`、`qa/validators.py`、`export/excel.py` 和 `cli.py` 增加边界校验与明确输入；补齐测试、打包元数据和必要文档。优点是变更小、可回滚、不会改变数据层结构；缺点是仍沿用现有模块边界，需要为 CLI 输入格式写清楚约定。

### 方案 B：只修采集器

只修改 ASIN、价格、恢复和月购买量，暂不处理 CLI、依赖声明和文档。实现快，但新环境仍需手工安装，导出仍可能缺图片/类目规划，不满足本轮审查的完整整改目标。

### 方案 C：重做 typed pipeline

围绕类型化记录重构采集、规范化和导出接口。长期可扩展性较好，但改动面大，容易影响已有真实数据和回归 fixtures，不适合当前“先修复高风险项”的目标。

采用方案 A。

## 3. 架构与数据流设计

### 3.1 详情页身份与访问门禁

`collect_details` 在网络响应和缓存恢复两条路径都执行同一套 `detect_access_status → require_normal_access`。正常页解析前，读取最终 URL（或页面中可靠的 canonical/ASIN 标识）并调用 `verify_asin_on_page`。若最终 ASIN 与请求 ASIN 不一致：

1. HTML 仍落盘为证据；
2. 该 SKU 不进入 `details.json`；
3. 记录可诊断的身份不匹配错误并停止该批次，避免错配继续扩散。

缓存恢复不能只搜索 CAPTCHA 文本；缓存文件必须再次通过完整访问状态检测，并同样执行身份校验。

### 3.2 价格与月购买量

- 原价选择器只接受明确的划线价格证据（`data-a-strike="true"` 或同等语义标记），排除单位价、配送价和普通辅助价格。
- 规范化层继续保存 `current_price_raw`、`original_price_raw` 和计算出的 `discount_rate`；缺少任一有效价格时不重建数值。
- QA 在原价存在且 `original_price <= current_price` 时报告价格异常；折扣率只在合法的原价大于现价时计算。
- 详情页和榜单页从可见的“上月购买”文案中提取 `monthly_bought_raw`，保存原文；`monthly_bought_min` 只表示文案给出的下限，不把评价、评论或排名换算成销量。无法解析时保留 raw（如有）并返回缺失/警告状态。

### 3.3 人工备注合并

导出前按 ASIN 合并旧工作簿备注：

- 新记录备注非空时优先保留新记录内容；
- 新记录为空且旧备注非空时回填旧备注；
- 两者都非空时不覆盖新记录，也不清空任一侧；
- 不用 QA 状态或自动文本替换人工备注。

### 3.4 CLI 导出输入

`export` 增加两个可选输入：

- `--images-dir`：按 `<ASIN>.<扩展名>` 查找本地图片，支持常见 PNG/JPEG；图片无法读取时只保留图片链接，不阻断整表导出。
- `--category-planning`：JSON 文件，接受字典行列表或二维数组；缺省时继续输出带标准表头的空 `类目规划`，不伪造内容。

CLI 将这些输入转换成 `export_workbook` 现有的 `images_by_asin` 和 `category_planning` 接口；西语表不嵌图，中文表仍按 ASIN 锚定图片。

### 3.5 包与文档

补齐 `pyproject.toml` 的项目元数据、运行依赖（BeautifulSoup4、lxml、openpyxl、Pillow、Playwright）和开发测试依赖，提供 `amazon-es` 命令入口。Playwright 浏览器安装仍需显式执行，不在安装包阶段自动联网下载。

同步修正 CURRENT_STATE、ROADMAP、ARCHITECTURE 中与现有 CLI、冻结字段和验证状态矛盾的描述，并补充离线安装/测试命令。

## 4. 错误处理与可观测性

- 访问受限（403/429/挑战页等）继续抛出 `AccessStopError`，不重试、不绕过；证据 HTML 保留。
- ASIN 重定向视为数据完整性错误，停止当前批次并提供请求 ASIN、最终 URL/页面 ASIN。
- 单个瞬时网络异常继续隔离，失败 ASIN 不写入正常结果，重跑可补齐。
- 图片加载、类目 JSON 或翻译缺失只影响对应导出内容；输入路径不存在、JSON 非法等命令参数错误要以明确消息退出。
- QA 输出保留现有 P0/P1/P2/P3 严重级别语义；月购买量的不可解析/不一致属于警告，不得误报为硬失败。

## 5. 测试与验收

实施前先为每个缺口添加失败测试和离线 fixture，至少覆盖：

1. 最终 URL ASIN 一致与重定向不一致两种详情采集路径；
2. 缓存正常页、缓存挑战页和无 CAPTCHA 的限流页；
3. 划线价与单位价并存时只取划线价；
4. 原价等于/低于现价的 QA 结果；
5. 月购买量西语文案的 raw 与 lower-bound 解析；
6. 新旧备注同时存在时新备注不被覆盖；
7. CLI 图片目录、类目规划 JSON 和缺失输入的导出行为；
8. `pip install -e .` 后命令入口、离线 `--help` 和全量 pytest。

验收标准：

- 全部既有测试和新增测试通过；默认不联网，live 测试仍只在显式 `RUN_LIVE=1` 时运行。
- 新建干净虚拟环境可安装项目及测试依赖，`amazon-es --help` 可执行。
- 变更不改变三张核心工作表的名称、顺序和固定列顺序。
- 不产生无证据的价格、销量、ASIN、类目或人工备注内容。

## 6. 实施顺序

1. 先写失败回归测试和 fixtures。
2. 修复详情身份/访问门禁、价格和月购买量解析。
3. 修复 QA 与备注合并。
4. 增加 CLI 图片/类目规划输入和包元数据。
5. 更新文档，运行全量离线验证与安装验证。
