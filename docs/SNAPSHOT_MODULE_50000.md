# 快照模块完善与 50,000 候选任务

本轮合并前期六项方案与 5 万条需求：配置与入口、配送预检、暂停恢复、来源配额、审查交接、实测性能。只在独立工作树开发、离线验证；不部署、不启动采集或翻译。

## 任务与数量契约

- 继续使用串行 V4 PAGE 引擎，不启用旧 ACP、多路执行器或新采集架构。
- 保留原有 20,000 与旧 30,000 密封策略；新增独立 10,000 / 50,000 策略。
- 50,000 指当次合格的全局去重保守候选组，不代表已确认可售 SKU。ASIN 仍是提示，身份冲突记录留置，不导致其他正常卡片停止。
- 50,000 默认来源最低量：畅销榜 15,000、新品榜 15,000、喜爱榜 3,000。前两项是防止来源失衡的下限，并非最终分配；三榜间有重叠，全局仍必须独立达到 50,000。喜爱榜下限满足后继续优先前两榜。
- 新配置的有限规划预算为畅销榜 2,200 页、新品榜 2,200 页、喜爱榜 600 页，共 5,000 个 PAGE 请求；不包含动态请求。不承诺这些页面一定能提供 5 万候选。预算不足必须报告缺口，不能自动放宽。
- 单榜预算耗尽只停该榜，其他榜仍在各自原预算内继续；不转移预算。全局预算、时间或访问门禁触发时仍停止整个串行任务。
- 维持请求间隔至少 3 秒、类目间冷却 1,800 秒、串行和原访问门禁。固定任务时钟 24 小时，包含中断和审查，不因暂停、修复、恢复而重置。时限不是完成时间保证。
- 配置、来源证据、计划、批准、预算和时钟仍分别绑定。生成配置或 pending 计划不授予 LIVE 权限，不创建运行时钟。

## 功能落地

| 方案 | 实现 |
|---|---|
| 统一入口 | `amazon-es snapshot` 薄适配现有 V4 CLI；原 `snapshot-v4.ps1` 和 `candidate-snapshot --offline` 保留 |
| 统一配置 | `profile` 生成有限配置，`prepare-page` 从已审来源生成新 pending 任务，不修改旧计划 |
| 配送预检 | 新计划显式绑定 `SPAIN_UI_PREFLIGHT_V1`；在业务拦截路由安装前复用正常邮编 UI，独立保存证据，不制造业务 HTTP Receipt |
| 页面门禁 | 预检成功不能替代逐页 Spain 和访问检查；Challenge 等保留原停止规则，未知 XHR/fetch 仍被拒绝 |
| 只读状态/预检 | `status` / `preflight` / `report` / `benchmark` 不创建原库或执行恢复；SQLite 在隔离副本查询，避免只读模式更新源 `-shm` |
| 暂停恢复 | `pause` 写入计划绑定的控制记录；页面保存后/冷却等待中停止；显式 `resume --release-pause` 才释放对应暂停，保留控制证据 |
| 恢复安全 | 保存页面先重放，已完成 URL 跳过；RESERVED 状态不自动重试；访问门禁不能由释放暂停解除 |
| 运行阶段 | 区分采集、类目冷却、最终 DOM 审查、用户暂停及停止原因；监控不把正常冷却/已声明的最终审查当作无请求卡死 |
| 卡片图片 | 新字段契约 `CARD_IMAGE_V1`，仅提取与同一卡片商品链接绑定的实际图片 src；不下载、不猜大图、不从其他商品借图；旧快照仍按原字段重放 |
| 候选筛选表 | `selection.csv` 保留品名、价格、评分、评价数、月购买量下限、类目、榜单、链接、图片和身份提示；完整证据仍在 candidates/observations |
| 统计 | 类目覆盖、跨榜重复、字段齐备度、冲突与排除原因；各类目/来源统计不可直接相加当成全局独立 SKU |
| 当前 PAGE 报告 | 独立报告适配，不套旧八来源/T2/30,000 门槛；保留 DOM、全部请求凭据、CSV/JSONL 回读检查 |
| 身份交接 | 输出候选及观察 provenance，不生成 READY/IDENTITY_COMPLETE。继续通过既有身份核验与 detail-plan；不直接把 ASIN 提示转成详情任务 |
| 性能 | 执行内凭据索引；无目的地复核记录的 PAGE 任务使用追加式增量统计。来源最低量跳过和总量停止前仍全量确认，结束仍全量重算/DOM 审查 |

## 离线命令示例

以下只生成待审配置，不能启动采集：

```powershell
amazon-es --offline snapshot profile --target-profile main-priority-50000 --out 'F:\ai文件\CodexStorage\work\AmazonESBestseller\snapshot50k.pending.json'
```

`prepare-page` 必须另外提供 `--base-plan`、`--base-authorization`、`--config`、`--task`、`--out`、`--runtime-root`，逐一检查原有来源证据。不得直接运行旧 runtime 下的私有准备脚本，也不复制旧任务的预算/时间延期授权。

已保存任务可使用 `snapshot status --root ... --run-id ...` 只读查看；`snapshot report --root ... --run-id ... --out ...` 重新独立审查并写入外部新目录。`snapshot benchmark` 分别测量数据库投影、文件读取、解析、完整校验、统计和导出。Windows 隔离读取默认临时目录位于 `F:\ai文件\CodexStorage\temp`；读完移除副本，原库不会被 SQLite 打开。若拷贝期间源库/WAL变化，拒绝不一致快照，稍后再读。

历史任务如缺少独立执行批准记录，报告明确给出证据不足，不补造历史批准，不将结构检查等同生产验收。新运行复用现有不可变 approval journal 保存执行证据。

## 验证与验收边界

- 用仓库保存的真实厨房榜单、三来源页面以及故障派生夹具验证字段和恢复。派生/模拟请求明确标记 TEST_ONLY，不能用于生产能力验收。
- 重放包含 20k/50k 配置、有/无喜爱榜预算修订、已保存未提交响应、参数顺序恢复、暂停/显式释放、只读报告及新任务准备。
- 负向覆盖：喜爱榜 2,999 时即使全局 50,000 也不通过；身份/证据冲突不得晋级；图片串卡/外域/多图冲突不得猜填；缺批准、缺请求凭据、被篡改证据不通过。
- 中文三表/26 列、原始西语和人工备注契约不变，本轮不导出或改写既有业务工作簿。
- 开发完成、离线测试通过、PR/CI、合并 main、运行目录更新和真实 5 万采集验收分别报告。没有开展新实采，不能声称 5 万供应、速度或正式生产已通过。

## 已保存真实数据的性能依据

2026-10-28 对原 20k 任务的 24,952 条观察做离线对照：全量统计 9.331 秒，候选聚合 6.690 秒；按每批 50 条进行追加统计，全部约 499 批共 4.095 秒，平均每批 0.00819 秒，最终与原全量统计每个字段一致。这是本地统计成本，不是网络采集速度。数据库投影/副本读取 12.899 秒，受磁盘缓存影响，不与冷读结果混为代码提速。

隔离复测覆盖 11,908 个原文件，大小/修改时间变化为零，观察数据摘要与首次读取一致。首次使用 SQLite `mode=ro` 测量时发现原 `index.sqlite3-shm` 发生更新；数据库、WAL 和其他文件元数据没有变化。没有删除或回写该缓存，随后修复为原库文件只复制、SQLite 只打开副本，并增加活动 WAL 读取且源 SHM 不变的回归测试。该首次结果不得记作“全部文件未变”的通过证据。

后续性能工作边界：优先减少累计投影/重复统计，其次才考虑解析与审查的重复工作。最终原始证据哈希、DOM 重放和身份门禁不能因性能原因省略。网站吞吐量、访问限制下的持续运行和 5 万真实唯一候选供应须在未来单独批准的任务中验收。
